01 / Enlaces

Empieza aquí

Publica una vez.
Cuídalo después.

Un enlace corto es una dirección que vas a poner en manos de otras personas. Comprueba su recorrido antes de imprimirlo o enviarlo.

  1. Decide el destino. Introduce la URL completa y comprueba que la página es la correcta. Revisa el alias y el dominio elegidos.
  2. Revisa las condiciones. Si hay reglas, confirma su orden y el destino previsto. Comprueba también caducidad, límites y protección por contraseña.
  3. Abre el enlace final. Hazlo en otro navegador antes de compartirlo. Para un QR, comprueba también una copia impresa a su tamaño real.
El cartel no cambia. El destino, sí.

Puedes editar el destino conservando la dirección corta. Una pausa interrumpe el acceso; enviar a la papelera no equivale a una eliminación definitiva. Revisa el estado después de cada cambio.

¿Y los parámetros de campaña?

Configura los UTM si necesitas identificar la campaña en la analítica del destino. Revisa la URL final, especialmente si ya contiene parámetros. Las métricas de UVH y las del sitio de destino miden momentos distintos y no tienen por qué coincidir.

02 / Dominios

Tu nombre, también en el enlace

Conecta tu dominio,
paso a paso.

Añadir un dominio al panel no basta para que reciba tráfico. Debe apuntar al servicio y tener una configuración TLS válida.

  1. Copia los registros del panel. Usa los nombres y valores exactos en el proveedor que gestiona tu DNS. No reutilices los de otro dominio.
  2. Comprueba la verificación. Consulta el diagnóstico y usa la comprobación manual cuando hayas guardado los registros. La propagación puede tardar.
  3. Verifica el recorrido HTTPS. Revisa DNS y TLS antes de distribuir enlaces. Que la propiedad esté verificada no demuestra por sí solo que el certificado esté listo.
Si sigue pendiente

Comprueba el subdominio completo y si tu proveedor añade automáticamente la zona al nombre del registro. Evita editar registros repetidamente mientras esperas la propagación.

03 / Equipo

Un espacio compartido

Cada persona,
su acceso.

Cada workspace separa sus recursos y miembros. Antes de crear, editar o invitar, comprueba qué espacio tienes seleccionado. Cada persona debe entrar con su propia cuenta.

Viewer
Consulta la información del espacio.
Editor
Trabaja con sus enlaces y recursos.
Admin
Gestiona el equipo dentro de los límites de su rol.
Owner
Conserva la responsabilidad y las operaciones reservadas al propietario.

Elige el rol mínimo necesario. Revisa los miembros cuando alguien abandone el equipo; no uses un token de API para sustituir una invitación personal.

04 / Analítica

Antes de sacar conclusiones

Un clic es una señal.
No una persona.

Una misma persona puede abrir varias veces un enlace. Los previsualizadores de mensajería, rastreadores y otros sistemas automáticos también pueden generar tráfico.

  • Compara el mismo periodo y los mismos filtros.
  • Ten en cuenta el estado del enlace, las pausas y los cambios de destino.
  • No interpretes una ubicación o un dispositivo como la identidad de quien accede.
  • Para ventas o registros, contrasta los clics con las conversiones medidas en tu sitio.
05 / API

Para integraciones

Tu primera petición
a la API.

Los tokens pertenecen a un workspace y tienen ámbitos de acceso. Para consultar enlaces, utiliza links:read. Para modificarlos, necesitas links:write.

Las integraciones con token usan /api/v1/public/links, no la ruta de sesión del panel. Guarda el token en el servidor o en un gestor de secretos: nunca en JavaScript público, una URL o un repositorio.

401

Comprueba si el token es válido y sigue activo.

403

Revisa sus ámbitos y el acceso al recurso.

422

Corrige los campos indicados por la validación.

429

Respeta Retry-After cuando esté presente y espacia los intentos.

Un timeout no confirma un fallo.

Antes de repetir una escritura, comprueba si el cambio llegó a guardarse. No reintentes operaciones de creación de forma ciega. Si un token se expone, revócalo y sustituye el secreto en tu integración.

06 / Webhooks

Eventos, no sondeos

Verificación
y reintentos.

UVH envía eventos como link.created, link.updated y domain.verified. Usa una entrega de prueba para revisar el receptor antes de depender de él.

  1. Conserva el cuerpo original. La firma se calcula sobre <timestamp>.<raw_body>. No reformatees el JSON antes de verificarla.
  2. Comprueba firma y antigüedad. Usa el secreto del webhook, compara el hexadecimal de v1 en tiempo constante y rechaza timestamps fuera de tu ventana de tolerancia. El timestamp está en milisegundos.
  3. Deduplica por event_id. Una entrega puede repetirse. Persiste el evento de forma duradera antes de responder con un estado HTTP 2xx.

UVH reintenta las entregas fallidas hasta cinco intentos. Consulta el historial antes de reenviar: un reenvío puede volver a ejecutar el efecto si tu receptor no deduplica.

Diagnóstico sin filtrar secretos

Registra identificadores de evento, estados y tiempos. No registres el secreto, la cabecera de firma completa ni cuerpos con datos sensibles.
